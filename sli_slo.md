# SLI / SLO для ML-системы прогнозирования спроса (управление складскими запасами)

## 1. Технический уровень (инфраструктура и сервис предсказаний)

### SLI
- **API latency (p95, p99)** — время ответа `/predict` и batch-инференса
- **Error rate (%)** — доля запросов с HTTP 5xx / failed inference
- **Uptime (%)** — доступность сервисов (API, модельный сервис, оркестрация)
- **CPU utilization (%)** — загрузка вычислительных ресурсов inference-сервиса
- **Memory usage (%)** — потребление RAM
- **Batch job success rate (%)** — успешность ежедневных прогнозных пайплайнов (Airflow)

### SLO
- p95 latency ≤ **200 ms** (online API)
- Error rate ≤ **1%**
- Uptime ≥ **99.5% / месяц**
- CPU ≤ **80%** (среднее за 10 минут)
- Memory ≤ **85%**
- Batch job success rate ≥ **98%**

---

## 2. Модельный уровень (качество прогноза спроса)

### SLI
- **MAE (Mean Absolute Error)** — средняя абсолютная ошибка прогноза спроса
- **RMSE (Root Mean Squared Error)** — штраф за крупные ошибки прогноза
- **Forecast bias (mean error)** — систематическое завышение/занижение спроса
- **Data drift (PSI / KS-test)** — дрейф распределения признаков (товары, продажи, сезонность)
- **Prediction drift** — изменение распределения прогнозируемого спроса
- **Missing feature rate (%)** — доля пропусков в ключевых признаках

### SLO
- MAE ≤ **baseline + 5%** или снижение MAE ≥ **10% относительно naive baseline**
- RMSE ≤ **baseline + 5%**
- Forecast bias ∈ **[-3%, +3%]**
- PSI < **0.2** (нет значимого дрейфа)
- Missing feature rate ≤ **2%**

---

## 3. Бизнес-уровень (эффективность управления запасами)

### SLI
- **Stockout rate (%)** — доля заказов, не выполненных из-за отсутствия товара
- **Fill rate (%)** — доля полностью выполненных заказов
- **Overstock volume (%)** — избыточные запасы относительно оптимального уровня
- **Lost sales (%)** — оценка упущенной выручки из-за дефицита
- **Inventory turnover** — оборачиваемость запасов

### SLO
- Fill rate ≥ **97–99%**
- Stockout rate ≤ **1–3%**
- Overstock volume ≤ **5–10%** от норматива
- Lost sales ≤ **2–5% QoQ**
- Inventory turnover ≥ **baseline + 5%**

---

## Критерии здоровья системы

Система считается стабильной и пригодной к продакшену, если выполняются условия:

- **Технический уровень**: сервис прогнозирования стабилен, отвечает в SLA, не деградирует по ресурсам и не теряет batch-задачи  
- **Модельный уровень**: ошибка прогноза (MAE/RMSE) контролируема, отсутствует значимый дрейф данных и смещение прогноза  
- **Бизнес-уровень**: повышается fill rate и снижается stockout rate, модель улучшает доступность товара и снижает упущенные продажи  

Критические триггеры деградации:
- рост MAE/RMSE > 10–15% относительно baseline
- stockout rate > 3–5%
- PSI > 0.25 по ключевым товарным фичам
- error rate API > 2%

При срабатывании критических порогов:
- переключение на предыдущую стабильную модель
- запуск переобучения через CI/CD pipeline (MLflow + Airflow)
