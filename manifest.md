# ML-манифест системы прогнозирования спроса для управления складскими запасами

## 1. Предыстория

Магазин сталкивается с дефицитом популярных товаров и избыточными запасами низкооборачиваемой продукции. Это приводит к потере продаж и увеличению затрат на хранение.

## 2. Ценностное предложение

Система прогнозирует спрос на товары и помогает поддерживать оптимальный уровень запасов. Это повышает долю заказов, выполненных без дефицита, и снижает складские издержки.

## 3. Цели

Прогнозировать спрос на товары, своевременно выявлять риск дефицита, формировать рекомендации по пополнению запасов и повышать долю заказов, выполненных без дефицита.

## 4. Решение

Заявляемый уровень зрелости ML-системы: **2**.

Архитектура включает полный MLOps-цикл. Исторические данные поступают в хранилище данных, проходят очистку и валидацию, после чего признаки сохраняются в Feature Store. Оркестратор Airflow запускает пайплайн подготовки данных и обучения модели. Эксперименты и версии моделей сохраняются в MLflow. После успешного обучения модель проходит автоматические проверки качества. Если значения MAE и RMSE лучше текущей продовой модели, CI/CD-пайплайн автоматически разворачивает новую версию сервиса. Модель предоставляется через REST API. Мониторинг отслеживает качество прогнозов, дрейф данных и бизнес-метрики. При деградации качества ниже установленного порога трафик переключается на предыдущую стабильную версию модели, после чего запускается переобучение.

## 5. Осуществимость

Необходимые данные, вычислительные ресурсы и специалисты доступны. Используются Python, Git, Docker, PostgreSQL, Airflow и MLflow.

## 6. Данные

Источники данных: история заказов, справочник товаров и складские остатки. Продовые данные поступают из ERP-системы и системы управления складом. Разметка не требуется, поскольку целевой переменной является фактический спрос в будущем периоде.

## 7. Метрики

Основная бизнес-метрика — доля заказов, выполненных без дефицита товара. Дополнительные показатели — количество случаев дефицита и объем избыточных запасов.

## 8. Оценка качества модели

Офлайн-метрики: MAE и RMSE. Онлайн-метрики: доля заказов без дефицита, дрейф данных, дрейф предсказаний и стабильность работы API.

## 9. Подбор модели

Итеративно сравниваются наивный прогноз, линейная регрессия, случайный лес и градиентный бустинг. В прод выводится модель с лучшими метриками качества.

## 10. Инференс

Инференс выполняется батчами один раз в сутки для формирования прогноза спроса и рекомендаций по пополнению запасов.

## 11. Обратная связь

Источники обратной связи: фактические продажи, случаи дефицита, онлайн-метрики и результаты мониторинга дрейфа. Все решения принимаются на основе данных.

MDD будет использоваться для принятия решений.

## 12. Управление проектом

Команда состоит из ML-инженера, Data Engineer и Backend-разработчика. Результат проекта — обученная модель, API сервис, Feature Store, мониторинг, MLflow, Airflow и автоматизированный CI/CD-пайплайн. Срок реализации — 2–3 месяца.
